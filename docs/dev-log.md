# 11 · 去人机味与整幅狂草

> 编者注：本文是项目研发期的原始记录。文中 `SKILL.md` 指早期的 Skill 说明（公开仓库对应 `README.md`）；命令中的 `src/` 已对应仓库的 `src/`。为保留过程真实性，正文未做改写。

## 一、问题：整体风格差得远、人机味重

早期出的字，单字都对、颜色也对，但和参考图并排就是"一眼 AI"。逐张放大对比后，人机味不是玄学，是**数字完美感**，来自三个具体层面：

| 层面 | 人机味（旧） | 真实感（参考图） |
|---|---|---|
| 字 | 纯白实心填充、边缘光滑、单字独立端正 | 偏灰、飞白镂空、连笔缠绕、墨有浓淡 |
| 背景 | 光影光滑渐变、清晰、无噪点 | 失焦、胶片颗粒、色偏、剪影 |
| 构图 | 字撑满、均衡、稳 | 留白、散点、松 |

## 二、三个调整杠杆（按重要性）

1. **换参考图（最关键）**：不要用"重笔/工整"的间接参考。直接拿目标风格的图、裁掉口令框和英文，做风格参考。模型对参考图的模仿远强于对文字描述的执行。
2. **提示词换框架：从"单字完整"切到"整幅狂草"**：允许牵丝连笔、缠绕、大弧线、简化；同时锁死字色（白就是白，参考图深色只是飞白不是字色）；字细、瘦、透、留白，禁止实心块面。
3. **胶片后处理兜底**：`film_post.py` 加颗粒、压灰、高光 halation、暗角，去掉最后一层光滑感。

## 三、整幅狂草的设计哲学（已写进 director.SYS）

除端庄题材（正剧/官方/纪念/纪录片，dignified=true）外，默认把整组字当一整幅狂草：

1. **一气呵成**：字与字牵丝连笔、笔意连贯，有大弧线、游丝，允许连写简化，但每个字轮廓在、整句读得出、一字不缺。
2. **细劲瘦硬**：以线条为主、笔锋锐利，不要粗壮、不要实心块面；大量枯笔飞白、斑驳镂空，笔画中间能透出背景，像干笔快速扫出来。
3. **轻盈疏朗**：整组只占画面中部、四周大量留白，不撑满。
4. **字色统一锁死、且立得住**：暗背景必须用明显亮于背景的字（亮白/青蓝/亮粉/荧光绿/红/紫），亮背景才用暗字；必须有明度差，不许铁灰/铅灰/深灰/暗褐这类撞明度的颜色。"柔和偏灰"是边缘柔、不是真用深灰。
5. **散点排布、大小有别**：重音字（关键名词动词）放大、笔稍粗，虚词连接字缩小细笔；放大的字仍细劲、不变实心块。
6. **简繁可混用**：不同字可分别用简体或繁体（书法常见），同一个字不繁简混写、都要规范可辨。

## 四、新增禁忌

- **T12 不逐字列清单**：提示词里把衬托字一个个列出来，模型会把清单当额外要写的字 → 重复字（"思、说"各出现两次）。只点要放大的主字，其余用"其余各字"指代。
- **T13 暗背景禁暗字**：导演曾选"铁灰 #5c6163"还写"与背景同明度"，暗背景上深灰字立不住。暗背景必须亮字、明度差要够。
- **T14 重笔不等于变黑**：写"重笔浓墨"模型会把该字画成黑色。要写成"颜色不变、只是笔画更粗"。
- **T15 不写死字数**：把 10 字写成 8 字会干扰模型。用"整句完整、一字不少"，不写具体数字。
- **T16 禁用"重墨/浓墨/藏锋/压住阵脚"**：模型把"墨"和"黑色"绑定，一写重墨就把该字画成灰黑（即使强调颜色不变也压不住）。要表现厚重，改用**形状/运笔语言**：圆笔粗画、圆头饱满、运笔慢而稳、敦实，并明确"粗细只是同一支笔的提按、所有笔画颜色一样亮"。
- **T17 句末字保护**：重音字放大后容易挤掉句末（"吗"多次丢失）。提示词结尾强制"最后一个字写完整、给它留位置，不许吞掉句末"。
- **T18 禁止均匀用力**：每个字都写得一样完整、一样卖力，是另一种单调。必须按强弱拍分配——主字肯定写到位、衬托字放松带过、部分压到极轻，拉开用笔的强弱（emphasis），不只是字号大小。
- **T19 粗重不等于变黑（比 T16 更深一层）**：模型先验里"毛笔粗重笔画"本来就等于黑色（真实毛笔字就是黑的）。光禁"墨/黑"字样不够，连"重按、粗实块、压住、提笔"这类动作词都会激活黑色先验，把主字画成黑字。解法：① 一律改用中性的形状词——"铺开、宽窄、收成细线"，不写"重按、实块、压住"；② 加无歧义的"字色铁律"：哪怕最宽的一笔也和细游丝同色同亮，宽只是形状、不是黑；③ negative_prompt 兜底（黑字、实心黑块、墨团）；④ 用白色狂草参考图锚定"粗块也是亮色"。
- **T20 模型不执行缠绕/枯笔，多半是提示词太长且自相矛盾**：一边要"缠绕、干笔"，一边又写"字间留空隙、不叠压、各自可辨、不合并"，模型为保"可辨"就退回安全的实心字。解法：① 砍短狂草分支、去掉冲突约束，只留"只要整句读得出即可"，鼓励大胆挨近缠绕；② 换更缠绕的参考图（caoshu_ref2，"荷风起"字字连笔），模型主要靠参考图决定字形，文字说不如直接给范本；③ 把"整字也可由干笔细丝组成"写明，给模型做极端枯笔的许可。

## 五、字段兜底（director.direct）

fresh 调用有随机性，导演偶尔漏填 background.prompt 或 color.name。返回前强制兜底：
- 背景缺 → 填"黄昏人物背影剪影、浅景深失焦、电线杆、模糊落日、紫灰天空、胶片颗粒"；
- 字色缺 → 填"亮白色"。
保证不出"纯黑空底 + 无景"的失败图。

## 六、刚柔并济（狂草的命门）

第一次做狂草，从"工整"矫枉过正到"有刚无柔"——每一笔都尖锐、出锋、快速甩出去，全在一个刚猛强度，成了狂躁的单调。参考图的狂草是**刚柔并济**：

- 刚：锋利果断的方笔、迅疾游丝、露锋；
- 柔：圆头饱满的粗线条、圆转的转折、运笔沉着、停顿呼吸；
- 方笔圆笔、提按快慢、露锋藏意交替，重音字敦实、虚词游丝。

关键实现（踩 T16 后才稳定）：**"厚重"只能用形状/运笔描述，不能用"墨色"描述**，否则一定变黑。多 seed 挑选（9404 偏圆、9405 有尖有圆更平衡）。

仍存的差距：参考图更疏、更轻、留白更大，我的字仍偏满、偏均匀用力，需要继续往"敢留空、敢极轻"推。

## 七、意境（最高要求）

"意境"不是玄学，是可拆解的整体氛围，靠五件事，已写进导演 SYS：

1. **留白**：敢空，大区域无细节的天空、雾，给想象，不塞满。
2. **虚实**：景全部失焦朦胧、以剪影轮廓为主，字相对实、带飞白。
3. **情绪锚点**：一个小而模糊的人物剪影（看不清脸），共情入口。
4. **强弱节奏**：主字肯定、衬托字放松带过、部分极轻（对应 T18）。
5. **统一色调**：全画笼罩在与情绪一致的色温里，情景交融。

实测 `9501`：雾中山峦、左下角孤独人影、青字、大量留白，意境首次成立。仍存差距：字偏满、强弱对比还不够极端，参考图的衬托字更轻、更敢留空。

## 九、横版高质量参考与装饰系统（16 张 HQ）

用户一次发来 16 张横版 1920×1280 的"真正好看"狂草图。逐张拆解后，除再次确认"细瘦飞白"方向，最大的新认知是我一直缺一层**装饰系统**。

### 1. 装饰系统：被 T6 锁掉的第二层呼吸

16 张里几乎每张都有，而我此前完全没有：

- **手写花体副标**：中文下方一行明显小的花体，内容是片名拼音（全小写连写，rimuhuoshaoyun、yanxing、fanchen）或一句贴合意境的英文（a haughty fish in the mortal crowd、stand still and gaze up at polaris）。必须手写花体、和中文同色、只作衬托，不是印刷体。
- **几何点线**：由小到大的圆点、细横线、小矩形框，对齐留白，做排版呼吸点。

这层装饰是"高级感/设计感"的关键，让画面从"中文+背景"的单调变成有层次的排版。**T6 就此放开**：不再一刀切禁止第二文字系统，改由导演自主决定加不加、用拼音还是英文、几何怎么排（字多情绪满可少加或不加，简洁片名适合加一组）。SCHEMA 新增 `decoration`（enabled/subtitle/geometry/placement），brief 按它注入，不再写死"不要其他文字"。

### 2. 新规律

- **T21 参考图本身的粗细，直接决定输出字的粗细**：caoshu_ref2（绿字主干粗）→ 字偏粗实；从 HQ 裁出 caoshu_ref3（hq_02 通体细白、去掉英文）→ 同句字立刻变细。换参考是控制字粗细最直接、最有效的杠杆，比文字描述更可靠。
- **T22 装饰要和句子意境绑定、且不喧宾夺主**：圆点可模拟火星、落在长尾上，花体与中文同色同色系、明显小；装饰是锦上添花，整体仍以中文和留白为主。
- **T23 简洁片名更容易做到通体细瘦缠绕**：字少、空间大，模型敢连笔、敢把整字交给细丝（凡尘即证）；多字长句的主干仍易被 8 步 turbo 写实心，长句可考虑增加步数或换更强模型。

### 3. 横版

这批全为横版 16:9（1920×1280）。single 已把横竖版参数化（按出图尺寸自动推断 orientation），不再写死"竖版"。

最新结论：装饰系统从无到有且与意境融合，细瘦缠绕在简洁片名上已追平参考；剩余差距集中在多字长句的主干仍偏实、字间牵丝可再强，后续可从增加步数或换更强模型入手。

## 十、稳定性工程：自动质检 + 换种子重试

用户问"能稳定输出吗"。诚实的前提是：**任何生成式模型都无法对单张结果做 100% 保证**，但可以用工程把"用户拿到的结果"兜到近乎必成。

### 1. 压力测试先行

用 2/4/7/10 字四个全新片名（惊蛰、山河故人、当时只道是寻常、人间烟火气最抚凡人心）连续 fresh 出图，**4/4 成功**：字全对、装饰齐全、无黑字事故。单张耗时约 100–140s（含导演设计 + 模型换入换出）。

### 2. 质检方法的演进（关键踩坑）

- **开放式 OCR 会漏字**：让模型"读出图中所有字"，狂草里写得轻、缠绕的字会被漏识别（小 OCR 漏「凡、只」，连 35b 也漏过「道」）。
- **封闭式核对消除漏识别**：把目标片名告诉模型，让它逐字确认"在不在图里"，只做有/无判断。实测合格图 7 字全 present、缺字图准确抓到。
- **T24 弱模型会"脑补"，质检必须用 35b**：qwen3.5:9b、gemma4:12b 会附和提示——既然你说应该有这些字，它就把缺的字也判成 present（实测缺字图被两者都判合格）。只有 qwen3.5:35b 强到能抵抗脑补、稳定抓出真缺字。

### 3. T25 出图后立即质检会撞 500，靠等待重试跨过

35b 是 20GB、在 12GB 卡上部分卸载运行。出图后立刻调用，常因 ComfyUI 还占着显存、ollama 返回 HTTP 500。解法：verify 遇错等待 5s 自动重试（最多 2 次），跨过瞬时显存竞争。**重试用尽不再"当作合格"，而是返回 `reliable=False` 的软放行**——明确告诉上层这次没核对成，由 stable_render 标记 `needs_review` 交人工验收，既不拖死流程、也不冒充通过。实测「长安三万里」第一次 500、重试后质检通过定稿。

### 4. stable_render 流程（single.py，软兜底不阻塞）

同一份导演规格，最多 `max_tries` 次，每次新 seed 出图 → 35b 封闭式质检。`quality.check` 返回 `(ok, missing, reliable)`，据此分三种结局：

- **质检通过**（reliable 且无缺字）→ 立即定稿，`status=passed`；
- **确实缺字** → 自动换种子重出；重试用尽仍缺字，返回最后一张、`status=needs_review`；
- **质检服务本身故障**（reliable=False）→ 不硬等，直接软放行、`status=needs_review` 交人工验收。

返回结果 dict：`dst / spec / prompt / attempts / status / missing / reliable`。原则是**自检只做兜底、绝不阻塞出图**——跑不通就放行，人工再验收，先保证出图质量与流程稳定。

### 5. 顺带修复：render_set 定义丢失

排查中发现 `single.py` 里 `render_set` 的函数定义行曾被误删，函数体变成 `stable_render` return 之后的死代码，导致多方案出图（网页 app.py、probe_set.py 都在调用）实际失效。已补回 `def render_set(text, hint="", k=4, seed_base=0, size=..., use_cache=True, font="cursive")`，并验证 `inspect.isfunction` 为真。

### 6. 默认关闭 Ollama 自检（出图已稳定，T26）

第二轮 2/4/5/7/10 字压力测试 5/5 全部一次出图成功、人工核对字全对，证明出图本身已经稳定。与此同时，自检的性价比已经反转：

- 每张出图后立即调用 35b，**第一次必撞显存竞争 500**，要等 5s 重试，质检给每张额外增加可观耗时和模型换入换出；
- 而它要防的"缺字"，在稳定管线上已经不再出现。

故决定：**默认流程直接单次出图、不再调用 Ollama 自检**。`stable_render` 去掉 quality 调用与重试循环，一次出图即返回 `status="rendered"`；`stability_test.py` 同步改为纯出图口径。`quality.py` 不删除、保留为手动旁路——个别重要图想逐字核对时，单独跑 `quality.check(text, path)` 即可。这是"先保证出图质量稳定、不为冗余校验付成本"的取舍。

新增脚本：`quality.py`（封闭式核对 + 重试 + reliable 标记，现保留为手动旁路）、`stability_test.py`（批量出图验证）。

最终结论：管线已能稳定产出高质量狂草片名海报，单次出图即稳定、字完整，默认不再做 Ollama 自检以省去 500 重试与额外耗时；质检能力保留为手动旁路，需要时可单独调用。剩余仅长句主干偏实的质感问题，不影响稳定性。

## 十一、好图四标准（最佳四张复盘，已写进 director.SYS）

用户明确：惊蛰、山河故人、当时只道是寻常、人间烟火气最抚凡人心这四张是目前最好的，意境与字体设计已较棒，虽还有一点差距。把它们与后来的南风知我意、长安三万里逐张对比，提炼出判断一张图成不成立的四条验收纲（缺一不可），并已作为【好图四标准】写进导演 SYS，让它在设计阶段就逐条对照：

1. **有纵深的具体场景**：背景不是一块空渐变，要有前、中、后三层——前景贴近且虚化的物件、中景承载文字、远景雾或山，并放进具体的叙事道具（惊蛰的草芽露珠泥土、当时的旧窗灰墙、人间烟火的路灯烟雾、山河的层叠远山），画面经得起细看。
2. **字景意象绑定**：要能讲出"为什么这个字配这个景"。闪电从"蛰"字引出、长笔压在山脊、暖字配暖灯烟雾——让一笔接上景里的线、字色呼应光源、拟物点题，字和景是一个整体，不是字浮在背景上的两张皮。
3. **敢做的字**：大小、粗细、缠绕、欹侧大胆拉开。"常"字是轻字的数倍、"惊"细"蛰"重，主字肯定写到位、衬托字放松轻带，拒绝每个字一样完整、一样卖力。
4. **有明确光源的统一色调**：画面要有说得清的光源（闪电、窗光、丁达尔光束、路灯、落日），整张笼罩在与情绪一致的色温里（冷青/蓝紫/灰蓝/暖黄），不要平光。

**为什么后来的南风、长安稍逊**：它们的背景收敛到"水面/旷野 + 落日 + 电线杆"的相似套路，叙事道具少、记忆点弱，长安还没出花体装饰。而最佳四张是同一次连续运行里四个独立 fresh 设计，导演给每张都换了完全不同的景和色调，构思密度与多样性更高。

**仍存在的"一点差距"**：参考图的飞白更通体、字更细，这四张个别主干仍偏实；惊蛰的双色字是双刃剑——亮背景上成立，放到暗背景易变黑。

配套四宫格：`ref_hq/best_four.png`。

## 十二、文化前置与去 AI 味（背景同质化的解药）

用户指出：凡尘最有意境、AI 味最少；背景存在同质化（万能情绪风景）；导演没有结合文化背景——千里共婵娟本该饮酒望月、白露缺少节气物候。

### 1. 凡尘为什么 AI 味少（复盘）

它刻意避开了"高饱和发光字 + 戏剧光源（丁达尔/灯泡/落日）+ 摆拍道具（芦苇/路灯/电线杆）+ 居中剪影"这套 AI 安全牌：低饱和青灰字、空雾山无道具、自然天光、字缠绕成一个整体、人物小而靠边。**高级感来自克制，不是堆道具加特效。**

### 2. 背景同质化的根因

- SYS 反复强调剪影/浅景深/失焦/统一色调，把所有背景收敛到同一套路；
- 兜底背景写死"黄昏+落日+电线杆+剪影"；
- 关键缺失：只要求"能拍到的具体场景"，没要求"先考证文化出处、节气物候，再让背景成为文化语境的视觉化"，导演于是用通用风景应付所有片名。

### 3. 代码改动（均编译通过）

- SYS 新增【先读文化，再定景】：先想清楚出处典故、节气物候、传统视觉符号，再写背景；判断标准"这个景只有这个片名才成立，换个片名还成立就是失败"。
- SCHEMA 新增 `cultural_context`（origin/imagery/why），direct/combo 补字段，_san 清洗。
- 修正好图四标准：第 1 条改为"文化特异性（最优先）"，第 4 条改为"自然的光与色调、克制不堆砌"，去掉堆道具/戏剧光的导向。
- 人物剪影改为小而靠边、不摆姿势；字色降低饱和与发光感，要像写在环境里。
- 兜底背景替换为中性的"清晨薄雾自然景物"，去掉黄昏/落日/电线杆。
- `single.brief` 注入 cultural_context.imagery，让绘图模型明确该出现哪些传统符号。

### 4. 第四轮验证：2-10 字 9 个片名，9/9 出图成功

先验证白露（《诗经》蒹葭、白露为霜）、千里共婵娟（苏轼中秋、长袍古人望月），文化语境准确；再跑 9 张，每张 48–88s（不质检更快），文化意象都真正画进了画面：

清明（祭扫人物/坟茔）、鹊桥仙（七夕深蓝夜/飞鸟）、枫桥夜泊（孤舟/古寺塔影）、人闲桂花落（金色桂枝/静坐人影）、枯藤老树昏鸦（扭曲枯树/归鸦）、独在异乡为异客（长袍古人/月牙）、清风徐来水波不兴（江舟/明月）、恰似一江春水向东流（雨丝/孤舟）、海上生明月天涯共此时（海面/满月/海边人影）。

### 5. 仍存在的小瑕疵

- 枫桥夜泊副标出现中文短语"寒山钟声落客船"（T9：导演把中文写进装饰、被画进画面）；

- 海上生明月有一笔金色（第二色，点题月光）；
- 暗调图底层仍有"雾+远山+剪影"的家族相似，属风格统一的必然，不算硬伤。

## 十三、现代非文化语境对照（第五轮，2-10 字）

用户要求再做一组不依赖诗词典故的现代语境，检验导演会不会给现代词硬套典故。选片：裸辞 / 打工人 / 末班地铁 / 今天不加班 / 成年人的崩溃 / 我在他乡挺好的 / 我们都在用力活着 / 有些路只能一个人走 / 这一年谢谢自己辛苦了。

关键观察：

1. **导演能区分两类语境**：现代词的 cultural_context 明确写"现代口语，无古诗出处"，意象落在地铁、写字楼、霓虹、夜街、便利店、残雪等当代场景，没有硬安典故；个别用自然/季节做轻类比（裸辞类比"相忘于江湖"、这一年类比"岁末自寿"），属修辞而非套典故。

## 十四、基于底图重绘（第六轮：元素驱动重绘）

需求起点：给一张实景照片，在这张照片的语境里配上标题。最初的设想是"给一张底图，让模型在上面添加文字"。

### 1. 保底图叠字这条路实测是死结（T27）

做法：底图 VAEEncode 成 latent，用中等起始噪声去噪，指望既保住背景又写上字。同一张皖南古村照片、同一份规格，跑了三档：

| 起始噪声 | 背景 | 文字 |
|---|---|---|
| 0.60 | 几乎像素级保住 | **一个字的笔画都没写上去** |
| 0.75 | 保住，但旗帜被改成白伞 | **同样没有字** |
| 0.90 | 主体保住，风机变多、旗帜消失 | 字出来了，但 18 字没写全 |

根因：**"保住背景"和"把字写进去"在抢同一份去噪空间。** 起点低，底图信号太强、模型不敢改，字进不来；起点高，能写字了，底图又被冲掉。turbo 只有 8 步，调不出稳定的甜点。

结论：**单靠调 sigmas 解决不了。** 只有 0.90 以上才写字，而那时它已经接近全流程，不如干脆走全流程。

### 2. 需求重读：是"捕捉元素重新绘制"，不是"保真叠加"

关键区分：

- 保真叠加 = 模型在原图上做局部编辑 → 抢去噪空间 → 死结；
- 元素驱动重绘 = 先读懂原图有哪些元素，再**重新画一张新图**把这些元素放进去 → 字走满流程，质量和原管线一致。

后者才是"捕捉原图的某些元素细节、重新绘制"的正确实现。改动只有一处：**不再 VAEEncode 底图，改用和文生图完全相同的空 latent 全流程**，把元素清单写进提示词。所以字的质量零风险，因为它就是原来那条路。

### 3. 实现（redraw.py，全新增文件）

- `design()`：一次 Ollama 调用同时拿到两样东西——`element_sheet`（scene / key_elements / anchor_elements / blank_areas / horizon / palette / light / mood）和完整制作规格（layout / font_design / morph / color / background / decoration）。**为什么合并**：35b 冷启动约 83 秒，识别一次、设计一次就是两次冷启动；合并后只加载一次。实测合并调用 84.8 秒出全套。
- `redraw_brief()`：字的部分与 `single.brief` 同源，背景部分换成"保留锚点"的约束。
- 出图前查 `/api/ps`，确认 35b 真在显存里才发卸载请求（`keep_alive: 0`），避免对未加载模型做无谓的加载再卸载；然后 sleep 4 秒让 ComfyUI 拿到显存。
- 规格缓存按 `片名|hint|底图 md5` 存 `redraw_cache.json`，同一片名配不同底图不会混用；`--fresh` 绕过。

### 4. 视觉模型选型：35b vs qwen2.5vl:7b

同一张图、同一道结构化 prompt：

| 维度 | qwen2.5vl:7b | qwen3.5:35b |
|---|---|---|
| 冷启动 | 17.7s | 82.9s |
| 热加载 | 2.1s | 十几秒 |
| 风机识别 | 第一次有、**第二次漏** | 稳定，且列为锚点 |
| 旗帜/研学队伍 | **两次都漏** | 准确识别蓝白旗、持旗游客 |
| 元素拆分 | 全塞进一个字符串 | 逐条带位置 |

判定：**7b 快，但漏掉的恰恰是这张图最不能漏的东西**——山脊风机是"新时代"的视觉锚，举旗青年是"青年"的锚；而且它同一张图两次结果不一致，不能作为可靠依据。正式重绘用 35b（自带 vision，无需另装模型）；7b 只留作快速预览。结论已写进 `config.REDRAW_VISION_MODEL` 注释与 SKILL.md。

### 5. 新增两条设计规则

1. **人物活动必须留住（T28）**：首版重绘把整队青年研学的人画没了，变成一张空景——因为导演只把飞檐、风机、古树选成锚点，没把"人"算进去。而"青年"正是片名核心。系统提示词补：照片里有人、有队伍、有活动，就要把人数、穿着、动作、朝向写进 key_elements，并且必须列为锚点，不许重绘成空景。补完后锚点变成"左侧 8-10 名白衣研学学生、右侧举手持蓝白旗的青年、山脊风机、飞檐"，成片人旗俱在。
2. **默认强制狂草**：导演会把"新时代伟大变革"这类宏大命题判成官方端庄场合（`dignified=true`），字随即变成独立端正、字号统一，狂草全没了（实测一张三行端正字）。本器主风格是狂草，所以在 `redraw()` 里默认把 `dignified` 压成 False，要端庄才显式 `--dignified`。

### 6. 工程隔离（用户明确要求"别让原有功能出问题"）

- 全部新增文件：`redraw.py`、`redraw_sweep.py`；`single.py` 一行未改（重绘直接复用它的 `_wf`）。
- `run.py` 只加 `--base` 分支：**传了底图才走重绘，不传完全走原文生图路径**。
- `config.py` 只新增 `REDRAW_VISION_MODEL`，不动已有变量；`preflight.py` 只新增 `check_vision()`（critical=False，缺视觉模型不影响文生图）。
- 回归验证：`run.py 晚风` 正常出图（白字狂草、末笔长尾、芦苇剪影），质量与原来一致；preflight 21 项全绿。

### 7. 实测结果

同一张皖南底图、同一句 18 字：

- 保底图 0.60 / 0.75 → 无字；0.90 → 字不全（作废）；
- 元素驱动重绘 → **18 字全对**，白衣青年队伍、举旗青年、白墙黛瓦飞檐、山脊风机全在，狂草细劲飞白、末笔垂入水面，青灰蓝色系统一。

对比图：`output/projects/title_generator/redraw_compare.png`（2x2，前三格是保底图三档的失败，第四格是重绘成功）。

### 8. 已知代价与遗留

- 是"同一个地方的重画"，**不是像素级保真**：机位、色调、锚点元素在，但细节会概括、光影会更电影化。要照片原样只加字，目前没有稳定解（T27）。
- 断行偶发不理想：成功案例出现 8+10 与 10+8 两种断法，"青年消费"被切开；字全对、读得出，但语义断点可用 `--hint` 指定行字数来约束。
- 一次 ComfyUI 崩溃（`aimdo memory compile error`，出在模型预取清理阶段），发生在连续多次 keep 模式出图后显存压力累积时，与脚本逻辑无关；重启服务即恢复。建议 keep 模式不要连续多档批量跑，recompose 无此问题。

## 第十五章　网图压力测试：字色、装饰色与极简构图

前十四章的验证几乎都在两张自家底图上做，容易过拟合。这轮从网上找 5 类实景做压力测试：海边日落、城市夜景、雪山云海、金色稻田、灯塔剪影，全部走 `--base` 重绘。

### 1. 四张首轮结果

| 片名 | 底图 | 字 | 问题 |
|---|---|---|---|
| 潮起潮落 | 海边礁石日落 | 4/4 ✓ 灰蓝狂草 | 拼音副标拼成 `chaogi`；夕阳暖橙被自己的"统一色调"抹成冷灰蓝 |
| 万家灯火 | 上海夜景 | 4/4 ✓ | **字是刺眼亮青蓝 + 外发光**，标准 AI 味 |
| 高处不胜寒 | 贡嘎雪山 | 5/5 ✓ 深墨青 | 无，明度差足、暖天光保住 |
| 稻花香里说丰年 | 金色稻田 | 7/7 ✓ 金褐 | 无，末笔"年"化成稻穗，拟物极佳 |

结论：**能不能成，几乎只取决于字色饱和度**。深墨青、金黄都成立，亮青蓝就毁。

### 2. 五个问题与修法

**(1) 拼音副标不可靠 → 默认全关。**
4 个字就拼错（潮起潮落 → `chaogi`），不是长句才有问题。`want_sub = False if subtitle is None`，要加才 `--subtitle`。

**(2) 光色指纹被"统一色调"抹掉 → REDRAW_SYS 第 7 条。**
模型能准确识别"左侧云层受光的暖色边缘"并写进锚点，却仍把 palette 判成"冷灰蓝"、background 写"紫灰色云层"——识别对了，调色时又被自己的"统一色调"规则覆盖。新规矩：照片的色温特征（夕阳暖橙 / 清晨冷青 / 灯火暖黄 / 雪原冷蓝）必须保留，不许写与真实色温相反的描述。

**(3) 字色高饱和 + 发光 → 程序化改色（本轮最大修复）。**
根因在 `director.SYS` 第 4 条，那条明确写着"暗背景必须用明显亮于背景的字（亮白、青蓝、亮粉、荧光绿）"，把高饱和亮色直接写进先验。但那条不能改——它服务于原管线。

更关键的实测发现：**提示词里写 hex 数值对模型几乎没有控制力**。把 `#7EC8E3` 降到 `#87c3d9` 写进去，出图仍是原来的亮青蓝，一个字都没变。真正的杠杆是**形态描述**。

所以改成三层处理，全部在 `redraw_brief` 里，与 director 隔离：

- 先摘掉色名里的发光词（"青蓝荧光"→"青蓝"），这些词一进提示词就诱导光晕；
- 用 PIL 算底图平均明度 `luma`，**只有暗底（luma < 0.45）且原色本身高饱和**，才把字色换成"接近白的浅色"（HLS 转 l=0.86 / s=0.18）；
- 亮底（luma ≥ 0.45）**不动**——金黄压稻田、赭红压雪原都成立，乱降饱和会把好图洗成土色；
- 原本就低饱和的浅色（如 `#dcebf2` 浅冷蓝）也不动，它本来就安全。

三张验证：万家灯火 luma 0.354 → 白字；稻田 luma 0.714 → 保金黄；雪山 luma 0.336 但原色低饱和 → 原样。

两个必须记住的坑：

- 阈值初版写 0.35，万家灯火 luma 0.354 刚好错过，白改一场；
- **绝不能按色相给字色起名**。`#d4dee1` 视觉上几乎无彩，程序按 h≈0.55 命名成"浅绿"，模型就真去画绿字。改成"接近白的浅色"才对。

**(4) 装饰色跑偏 → 剥离颜色词。**
geometry 文案是"右侧三个由大到小的**淡青色**圆点"，模型就真画青绿圆点，和白字打架。程序把颜色词摘掉（含"淡青/青绿/琥珀…"和`淡|浅|深|亮|冷|暖`+色字组合），再强制"跟字用同一个颜色、不另配色"。删完会留孤零零的"色"和"冷圆点"，要二次清理。

**(5) 极简剪影被画成特写 + 凭空加元素 → SYS 第 9、10 条。**
灯塔图是"天地间小小一个黑影、四周大片空茫"，靠比例撑起孤寂感。重绘把灯塔放大成占满画面的特写，还加了道闪电——意境全毁。新规矩：不许添加底图没有的元素（闪电、飞鸟、额外建筑）；留白和比例也是构图，主体小、空茫大就得保持。

### 3. 修后对比

| | 修前 | 修后 |
|---|---|---|
| 万家灯火 | 亮青蓝发光字，绿圆点 | 白字压紫蓝天，不发光，圆点同色 |
| 孤灯照海 | 闪电、冷灰、灯塔特写 | 粉紫霞光回来、无闪电、暖白字、末笔化浪花 |

### 4. 遗留

- **字偏大**：极简图上 4 字会撑满整幅宽，"孤"感被削。brief 里的"整组字收小成一块"仍是软约束，模型不总执行。要彻底控制得另做字号约束。
- **锚点密度会波动**：万家灯火修后色彩对了，但陆家嘴楼群比修前稀。重绘的随机性在"密度型"锚点上仍有损耗。
- 一次 CUDA `Sticky error detected`（`cudaMemGetInfo` 报 `unknown error`），ComfyUI 进程活着但所有请求 500，且新进程因 `comfyui.db` 被占用起不来。处理：`Stop-Process` 掉旧进程再 `launch_comfy.py`，否则会卡在数据库锁。

## 第十七章　重绘三问题收口，与透明背景文字功能

### 1. 重绘三个问题的修复

第十六章暴露的三个问题，这一轮逐个修掉并做了回归：

| 问题 | 根因 | 修复 | 验证 |
|---|---|---|---|
| 多字/重复字（雨夜独行多一个「行」） | 提示词只防「缺字」，没防「多字」 | 字约束改成「恰好 N 个字、不多写、不重复、写完即止」，结尾再加一次总数复核 | 重跑雨夜，恰好 4 字 |
| 锚点不落地（大漠「一缕烟」丢失） | 泛泛说「要可见」，模型对无实体元素没位置感 | 检测烟/雾/光/尘类虚锚点，单独给「画在棱线后方、被逆光勾边、肉眼可辨」的位置形态指令 | 重跑大漠，烟柱明确出现 |

工程上仍只改 redraw.py，single.py/director.py 一行未动；回归抽查归途、18 字，原有用例没有变差。

### 2. 透明背景文字：T27 死结的真正解法

重绘再怎么优化，「保背景」和「写字」始终在同一张图里抢去噪空间。透明文字从根上绕开：**直接生成一张只有字、没有背景的 RGBA 图**，原图一个像素不动，把字层叠上去即可。

Qwen-Image 2.1 的 VAE 是四通道，透明背景由模型直接生成在 alpha 通道里，不是事后抠图——这是它在主流开源模型里独有的能力。

新模块 `transparent_text.py` 的关键设计：

1. **不调用 Ollama 导演**。提示词自包含狂草约束，只走 ComfyUI，所以不抢显存、出图快、可复现。
2. **字形（alpha）与字色分离**。模型把笔画浓淡飞白画进 alpha，最终 RGB 由程序统一着色。
3. **程序化着色顺带消除彩色污染**。实测模型出的半透明飞白边缘会混入蓝紫色杂边（在深底上明显）；保留 alpha、把 RGB 全部换成指定的一个字色后，杂色消失，浓淡仍由 alpha 自然呈现。

### 3. 验证数据

5 个用例（2/4/7/10/18 字，共 41 字）：

- 全部输出 RGBA，背景透明像素约 37–39%，**41 字全部正确**，无缺字、多字、错字
- 统一暖米白，蓝紫杂边 0、发光 0，飞白狂草与主次都在
- 端到端叠到原始森林、夜市照片上：原图零改动，字清晰可辨

### 4. 透明文字 vs 重绘：怎么选

| 维度 | 重绘（recompose） | 透明文字（alpha） |
|---|---|---|
| 背景 | 重画一张，元素靠提示词落地 | 原图 100% 保真 |
| 字的位置 | 智能压留白、避让锚点 | 默认占满画布，需后期调位置大小 |
| 融合感 | 字与景同一去噪过程，有空气感 | 字是「贴」上去的，无环境光交互 |
| 随机/复现 | 有生成随机性 | 固定 seed 可复现，颜色随便改 |
| 适用 | 要意境、要字景交融 | 要保真、要快速、要可反复改字色位置 |

两条线并存，按场景选，互不影响。

### 5. 工程层面的老问题

这一轮又触发了一次 CUDA sticky error（在透明文字首次渲染时）。处理流程已固化：停掉轮询任务 → 确认无残留进程锁 → 重启 ComfyUI → 续跑。CUDA 崩溃后 ComfyUI 偶尔会在启动早期静默退出，需要直接运行 main.py 捕获、或重新拉起一次。当前仍非无人值守。


## 第十八章　书写过程视频：H3 的三条硬规则（可选功能，默认不调用）

### 1. 定位

把已经出好的海报当末帧，让本地 MiniMax H3 从「同场景无字底版」把它一笔一笔写出来。5.2 秒、768×448、带模型自己生成的音轨。

**默认不调用**：`run.py` 没有视频分支，只有显式跑 `src/write_video.py` 才用。理由不是做不出来，而是性价比——额外 44GB 权重、单条 110–120 秒、约 1/4 概率要重跑，不适合进常规出图链路；它更适合单独做片头、社媒封面和答辩演示。

最初的判断错了一次：先按官方文档认定 H3 在 ComfyUI 里只是按秒计费的云端节点，建议放弃；实测发现 0.45.0 内核里就有整套本地节点（`comfy_extras/nodes_minimax_h3.py`），权重也早已就位。**结论必须以实机为准。**

### 2. 三条硬规则

| 规则 | 违反后的现象 | 机理 |
|---|---|---|
| 首帧必须完全无字 | 不写字，只是从模糊变清晰 | 首帧里有字形残留，H3 选「对焦」这条最省力的路 |
| 首尾帧必须同构图 | 中段切到「手指着纸写黑墨」俯拍特写；或整支演成黑底金字片头卡；或从黑场淡入 | 构图差太远时它必须找个转场方式，而「纸面书写」和「黑底金字标题卡」是它最强的两个先验 |
| 提示词不提手、不提笔、不提纸 | 同上，且墨色变黑 | 一出现这些词就调到纸面黑墨先验；`cfg=1` 时否定词基本无效，把「不要黑墨」写进去也拦不住 |

这三条互相打架：要写字就得首帧无字，要不跳场景就得同构图。唯一能同时满足的，是**同一场景的无字底版**。

### 3. 无字底版（这轮真正的结构性收获）

用重绘那套已经识别好的元素清单、同一个种子、同一套 workflow，把写字相关的句子全部去掉再出一张：同一个地方、同一批人、同一个时刻，干净无字。12–17 秒。

它的价值不止于视频：**底版 + 透明字 + 成片三件套闭合了**。静态海报的分层交付、以及后续任何形式的动效（H3 的、程序化的）都建立在它上面。所以优先级上，底版高于视频——视频只是底版的第一个消费者。

首帧还会按末帧的逐通道均值/标准差做一次亮度对齐。大漠那张首帧均值 115、末帧 143，未对齐时 H3 直接无视首帧，生成的第 1 帧均值 0.0（纯黑），自己演成黑底金字片头卡；对齐后正常。

### 4. 「按笔画写」到底难在哪

分两层：

- **严格笔顺（先横后竖）做不到，是架构性的**。视频扩散模型没有笔顺语义，它只按自己的先验把字形演出来，无法指定第几笔先下。提示词、步数、首尾帧都改不了。
- **「逐笔生长」做到了**。实测第 15 帧只有起笔那一横，第 40 帧半个字，第 80 帧第二行写到一半，第 124 帧收完。观感就是一笔一笔写出来的，只是这个顺序由模型自己排，不是书法笔顺。
- 真要严格笔顺只能走程序化：墨迹骨架（Zhang-Suen 细化）切段 + 段间停顿。骨架已实测可算（惊蛰 1/4 降采样后 2401 个骨架点），但会换掉整套审美，不作为主线。

### 5. 数据

|---|---|---|---|---|---|
| 雨夜独行 | 4 | 无字底版 | 4/4 | 116 s | 通过 |

### 6. 成本与稳定性

- 单条 110–122 s（768×448 / 124 帧 / 8 步蒸馏）；1344×768 约 3 倍。
- **提示词必须短**：H3 的文本编码器 14.6 GB，在 12GB 卡上长提示词把激活内存撑爆，进程直接 `Fatal Python error: Aborted`（崩在 `comfy/text_encoders/minimax.py` 的 forward）。提示词压到 110–130 字后稳定。
- 偶发 `CUDA error: an illegal instruction`（MiniMaxH3ImageToVideo 节点），重启 ComfyUI 进程即可；sticky error 不重启清不掉。
- 音轨是模型原生生成的 AAC 32kHz 立体声，与画面同步（采样数 330668 是双声道展开后的数，实际 5.17 s）。内容不完全受控：雨夜给的是持续雨声，大漠几乎静音，夜市给了市集人声。
- 末帧是重新演绎、不是像素级复刻。雨夜那张它顺手修掉了我们成片右下角重复的小「行」，但也意味着海报与视频末帧的字会有细微差异——做品牌物料时要么接受，要么把视频只用在「海报出现之前」的段落。

### 7. 和程序化动效的分工

- 量产动图 / 社媒封面 → 走程序化 alpha 揭示。透明字层 41/41 字全对，1080p 零成本、零失败率、字形与海报 100% 一致。
- 片头 / 答辩演示样片 → 走 H3。它唯一不可替代的，是笔尖真的在长笔画、有模型自带的手劲和随机。

### 2. 副标：从「不许出错」到「默认不出」

第 2 张模型自拼了 `luoxiaguwu`。一开始按旧认知把它记成缺陷，用户的纠正改变了整个设计：

- 「**我不是反对拼音和英文副标，我只是希望别出错**」——副标可以有，文字必须可靠。
- 「**你不要盲目加拼音，需要加再加**」——所以默认不出，`--subtitle` 才出。

落到代码是「文字一律程序生成」：`src/subtitle.py` 用 `pypinyin` 逐字算拼音，多音字走词组词典，英文只在调用方显式给出时出现，模型不再有任何自由翻译的空间。`HAS_PINYIN` 为假时返回空串——**宁可不给，也不出错**。提示词里再用 `RULE` 把字母串钉死。

实测：`落霞孤鹜 → luò xiá gū wù`、`银行行长 → yín háng háng zhǎng`、`长沙 → cháng shā`、`重庆 → chóng qìng`、`音乐 → yīn yuè`。可视化复验一张（seed 363574，1536x864），四个字与副标全部正确。

### 3. 透明字薄雾：alpha < 18 一律归零

第 6 张竖版 864 宽，全透明 36.1%；第 7 张 1920 宽，全透明只有 4.5%，另有 83.4% 落在 alpha 1–64。同一功能两套口径，差别只在画布宽度。

原因是大画布上模型会顺带给整张画布铺一层 alpha 1–64 的「纸感」，叠到亮底就是几条脏痕。而飞白细丝的 alpha 实测都在 40 以上，所以 `tint_alpha(img, hex_color, floor=18)` 把 alpha < 18 的像素归零，**只砍雾、不砍笔画**。

复验（seed 880222，1920x1080）：全透明 87.6%、alpha 1–64 仅 0.5%、其余 12.0% 是真实笔画，bbox 覆盖字形范围。薄雾没有了。

### 4. 1080 变 1088：VAE 的 16 像素对齐

第 7 张请求 1920x1080，落盘 1920x1088。VAE 要求 16 对齐，1088 = 1080 向上取整。这不是模型抽风，是硬约束，只能事后裁。

`single._save_out(fn, sub, kind, text, seed, size)` 增加 `size` 参数，尺寸不符时按请求尺寸居中 crop；四个调用点（`single`×2、`set`、`ref`）与 `redraw` 的落盘全部传入 `size`；`transparent_text.generate()` 在 tint 之后同样居中裁回。复验三条路径都打印 `[crop] 1920x1088 -> 1920x1080`，产物严格等于请求尺寸。

### 5. 亮底字色：一次失败的反向实验（重要）

第 1 张（亮底黑字）与第 8 张（亮底白字、几乎没入雾）同源，都指向 `brief()` 里那条绝对铁律：「全图没有黑字」。

- **第一版改法**：换成「字色必须与所在背景有明度差——亮底压深墨色、暗底用亮白」。结果可读性立刻好转（seed 362820 六个字全部清晰；seed 362830 人间值得的黑墨压在雪原上，非常好看），但模型把「亮处压深」理解成了**同一张里黑白混用**：黑墨主体 + 白飞白。
- **第二版改法（失败）**：把规则收紧成「先判断整幅明暗、只定一个颜色、亮处不许混白字」。同种子换一个重跑，末字反而整字变白——「得」压在雪地上几乎读不出，比第一版更糟。

结论：**黑白混用是 turbo（cfg=1）下的模型先验，措辞压不住**（cfg=1 时 negative 本就无效）。回退到第一版措辞，并把「亮底会不会出黑白混用」写进已知限制。观感上「深墨主体 + 白飞白」像真迹、可读，接受。

## 二十、ink-rhythm：给笔画加提按与浓淡（默认关闭）

起因是一句外部评价：“笔画偏平，缺少浓淡变化。”对照成图后，这个判断有六七分成立：`惊蛰` 有主次，但青色笔画内部明度、宽度都比较均匀；`稻花香里说丰年` 金色字整体顺滑，同一明度、同一笔触感偏长，更像精致笔刷。根因不是模型不会写重笔，而是提示词为了压“发光/黑墨”，一直强调“细瘦、缠绕”，把重按和墨块一起压掉了。

这次没有推翻默认，只加了一个 `ink_rhythm=False` 的 opt-in 分支。`config.INK_RHYTHM_LINES` 追加三条：每个字内部至少一处重按、一处提起；重按仍是原字色、只是更浓更厚实；每个字只压重一到两笔，重笔分散、整组浓度接近。`single.brief` / `redraw.redraw_brief` 在开关打开时，把三处会压平层次的硬约束换成同色浓淡版本：细劲为主但提按分明；干丝是同一字色的淡墨；最宽一笔可以在同一色相内更深，最浓处仍透出飞白。默认路径一字未改。

A/B 用 2/4/7/10/18 字五组，同规格、同 seed，只切开关。结果：2 字「惊蛰」浓淡成立，但「蛰」偏淡；4 字「人间值得」起笔重、收笔细，四字清楚；7 字「稻花香里说丰年」七字全对、无发光、锚点在，但首字「稻」深金重压、其余六字偏淡，浓度不均；10 字「人间烟火气最抚凡人心」白色字有粗有细，最接近真迹感；18 字长句全对、无重复、无发光，首字「从」重、其余保持蓝绿。像素差异 13.7–22.6 mean abs，证明不是同一张图。

结论：`ink-rhythm` 可以做出可见的提按/浓淡，但还不是默认产线的替代品；7 字金色案例需要换 seed 复验，长任务仍需人工核对。默认继续保持关闭，README 与 CHANGELOG 已写明开关和已知问题。

## 二十一、把实验开关拆成两个正式接口：整齐版 / 浓淡版

A/B 交付后，用户看完对照的反馈是：「后面一版感觉好点，能不能做成两种接口，整齐版和浓淡版。」这句话同时确认了两件事：浓淡方向值得保留；但它不该继续以一个藏在 CLI 深处的实验开关存在。

于是把「开关」提升为「版式」：

- `neat` = 整齐版：v0.1.0 的细劲、缠绕、整组同亮度，继续做默认；
- `ink` = 浓淡版：原来的 `ink_rhythm=True` 路径，字内提按、同色浓淡；
- `config.STYLES = (neat, ink)`、`STYLE_LABELS` 与 `resolve_style()` 做统一解析，`style` 优先，旧 `ink_rhythm=True` 兜底成 `ink`，都为空则 `neat`；
- `single` 的 `brief / render / _render_with_spec / stable_render / render_set / render_one` 全部带 `style`，另加 `stable_render_neat` / `stable_render_ink` 两个 Python 入口；
- `redraw` 同步加 `style` 与 `redraw_neat` / `redraw_ink`；`transparent_text` 的 `alpha_prompt / generate` 也接受 `style`；
- `run.py` 主入口改用 `--style neat|ink`，`--ink-rhythm` 保留为兼容写法，和 `--style neat` 同时出现时直接报错，避免「嘴上说整齐、实际开浓淡」的静默错配；
- 工作台在「笔法」之后新增 `05 墨版` 区块，两个 chip 写入任务参数 `style`，并随表单持久化。

默认仍选整齐版，理由不是审美，而是稳定性：五组 A/B 里 7 字金色案例在浓淡版下首字过重、其余偏淡；整齐版没有这个结构性风险。浓淡版作为明确可选项，交给用户按文本长度、底色和字色决定。默认收口到 `config.DEFAULT_STYLE`，将来想全局改成浓淡版，只动这一行，不用改四个 CLI。

验收用「惊蛰」、同一份导演缓存、同一 seed 325399，仅切 `style`：两张图 mean abs 22.15，76.4% 像素超过阈值；整齐版整组墨色更实，浓淡版「惊」重、「蛰」转淡，差异肉眼可见。产物在 `D:\ComfyUI\output\projects\title_generator\style_interfaces`，不影响仓库。
